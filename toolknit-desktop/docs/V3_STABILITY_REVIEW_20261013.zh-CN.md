## 缩略图与原图

此前 native history 已缩小到 300×180，但每次获取历史仍重复解码原图并重新生成预览。
本轮增加 `Arc<OnceLock<Result<String, String>>>` 缓存，缩略图在原有 `spawn_blocking` 中首次生成，后续共享复用。
原图 PNG 独立保留；打开查看器仍按截图 ID 获取完整原图，保存、复制及 OCR 不使用缩略图。

历史 UI 缓存只持有当前列表节点与预览。删除过期记录或销毁窗口时释放，继续保留最多 10 张历史和原有 64 MiB 编码容量边界。
没有降低用户原图质量，也未新增图片库或模型。PNG 压缩体积依图片内容变化，不能用固定压缩倍率作承诺。
缩略图失败仍保留旧列表并提供重试；过期异步更新不提交到新状态。

## 契约与限制

本轮未新增 native command、事件、storage key、DOM ID 或 CLI/MCP 能力；只新增 `common.windowControlFailed` 双语提示与专项测试。
工具重依赖仍懒加载，主入口未进行全量重构。既有 crypto externalization、大 chunk 与 Windows linker 提示保留。

用户反馈的偶发关闭需再点其他按钮、托盘恢复后导航消失，本轮未在真实 Windows 主 WebView 中复现。
已消除可验证的动画无限等待、原生动作竞争/无回复阻塞以及恢复状态未同步的风险，但无法把这些风险认定为唯一根因。
原生调用超时只解除前端等待，不能取消 Windows 已收到的命令；迟到回复不再阻塞后续操作。
系统登录/重启、多显示器 DPI、长期常驻与机器实际帧率仍属于原生环境验收范围，浏览器模拟与合帧次数不等于固定 60 FPS 承诺。

## 维护复盘

缓存优化需证明重复工作减少，同时证明原图契约不变。异常测试应重放“动画/原生回复不返回”和“旧查询迟到”，不能只验证成功路径。
共享导航新增按钮时按语义定位，而不是依赖按钮排列；来源返回与输入释放必须一起验证。
下次真实原生复现时记录当前页面、最小化/最大化状态、活动遮罩和焦点事件顺序，避免没有证据就重写全局导航或归因于反复安装。
